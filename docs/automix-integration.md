# AutoMix 接入

来源：用户提供的 `automix.zip`。`player-core/audio` 下的 `core`、`decode`、`dsp`、`mix`、`model`、`stem`、`studio` 子包迁自原包，日志改接 QPlayer。未打包 CLI 或 JCodec MP3 解码器；Android 使用 MediaExtractor / MediaCodec 解码。原第三方说明保存在 `player-core/src/main/resources/automix/THIRD-PARTY.md`。

设置中 AutoMix 替换旧智能过渡、曲线、节拍对齐、低频互换和 ACE-Step 转场设置。沿用旧总开关键以保留用户开关偏好；新参数使用独立键，默认本地智能混音、auto 风格、6 秒固定窗口。智能混音不调用聊天 AI 接口。AI DJ 和 AI 歌单的配置不变。

固定窗口默认开启；手动调整“过渡时长”会同时启用并保存固定窗口，即使再次提交相同秒数也生效。已有明确保存的自动窗口选择在加载时保留，用户仍可主动关闭固定窗口恢复原版自动策略。两项设置一起推送，避免以新秒数和旧自动策略启动制作。过短歌曲仍遵守至少播放 5/7 与剩余音源约束。

“自动点位”是独立开关，默认开启，提示为“有可能吃掉下一首歌一分钟”。关闭后仍保留混音风格、节奏/和声分析，但不跳过下一首开头、不提前裁掉当前曲尾部；“固定过渡窗口”只控制窗口搜索，与点位开关分开。

前一首歌曲至少播放到总时长的 5/7（约 71.43%）才允许开始融合。自动搜索、固定候选点、结构对齐和拍点微调均遵守此下限；例如 3 分 30 秒的歌曲最早在 2 分 30 秒开始融合。窗口约束在引擎准备素材之前传入，过短歌曲才缩短窗口。最终制作再次检查实际音源时长，拒绝非法点位，不再把原版风格静默替换成普通交叉淡化。

窗口策略对照原包 `AutomixCli`：自动交叉/和声模式在设定值附近搜索，智能模式按风格与拍数决定实际时长。QPlayer 的“固定过渡窗口”额外明确为所有三种混音模式都严格使用设置的秒数（受 5/7 与剩余音源约束）；固定时不由节奏斜坡、窗口缩放或循环买时间改写时长。智能模式保持原有选风格、空间宽度、滤波、EQ 等处理。关闭自动点位使用真实曲尾/曲头，保留选中风格与防削波；搜点失败亦使用同一风格的曲尾/曲头，不把分析缓存的长度误作要丢弃的曲尾。

分段素材与循环按引擎的实际边界拆块，并保留两侧未消费采样；过渡最后一块使用实际帧数计算进度。循环延长时采用明确的源歌曲出场坐标，避免用“歌曲时长 − 延长窗口 − 曲尾”反算出过早点位；循环引擎已提供 A 素材时，不因原曲已经结束而中止制作。续段按 B 的真实时长写入，允许的长度误差只限于源采样率换算的末帧舍入，显著提前耗尽会报错。制作成功时详情页显示实际融合秒数、A 出场点、B 入场点以及歌曲进度倒计时。

完整曲目对照：`ReferenceParity.java` 使用原包 FileDecoder 和用户给出的 The Color Violet / Heartless WAV。6 秒固定交叉（伸缩关）的出场 195.605 s、入场 4.284 s、窗口 6 s；自动和声的出场 198.605 s、入场 8.700 s、窗口 3 s；智能 auto 的出场 198.605 s、入场 8.937 s、窗口 3 s。三种均与未修改的 `automix.jar` 决策吻合；输出 WAV 的 B 续段长度和原曲时间轴误差小于 2 ms。原版和声/节拍算法保留，用户要求的降调/音量平滑与 5/7 下限作为明确扩展保留。

“过渡降调”使用独立设置键 `autoMixPitchEnabled`，默认开启，保持已有融合效果。关闭后两侧 `pitchAt` 和计划音高均归零，两首保持原调；自动点位、窗口、风格、节奏和人声处理继续生效。修改会使旧参数成品失效，下一次制作用新参数。

降调渐变按最终渲染窗口的真实秒数计算，和声及智能模式用约 2.5 秒平滑进入目标音高，末尾用约 2.5 秒回到原调。短于 5 秒的窗口由两段渐变各占一半；大幅移调同样渐变并归零，避免进入连续原调尾段时骤然跳变。自动点位调整窗口时不会把 2.5 秒压缩为原先的比例时长；关闭降调仍全部为零。

智能混音的互补频段削减使用同一时间曲线，逐采样从原声渐入滤波，避免融合第一块直接套用整组削减、导致音量立即下降。A 的削减逐渐进入，B 的削减在尾部逐渐退出、接回原歌曲音量；单频段及多频段路径一致。滤波器始终处理信号以保留连续状态，原防削波逻辑保留。真实 1kHz 信号回归验证起点原音量、约 2.5 秒渐变、短窗口、多频段和 B 尾段还原。本地试听新增 `-AutoCue` 可复现 App 默认自动点位，试听前缀按成品实际 exit cue 提取。

“提前缓存下一首”默认开启，AutoMix 关闭时也可预取音频。AutoMix 开启时，将完整缓存所需音源作为制作前置步骤：下一首下载完成后再准备当前音源，随后开始制作。网易云使用正常播放的歌曲缓存；自定义音源使用独立来源键。下载原子落盘，取消/错误不留下可播放的半文件，制作中的源文件通过 lease 防止 LRU 淘汰。播放详情页（默认及 Claude 布局）显示缓存、制作、制作成功或失败回退状态，切歌后清除上一组标记。

Android 播放流程：提前分析相邻音源，用原 Transition 实现生成混音段，并在同一 WAV 中继续写入下一首的剩余音频。Deck 负责重采样、声道转换和移调。完成后停放在第二个 MediaPlayer，抵达原算法的 exit cue 时交接。下一首的进度映射回原曲；用户拖动进度时重开原曲对应位置，可返回被裁去的前奏。B 继续播放时不会在混音末尾重新打开，因此没有重复前奏的第二次交接。

压缩音频的容器时长可能包含编码延迟/尾部 padding，而 Android MediaCodec 已将其裁去。制作允许有损音源最多 4096 个源采样帧加重采样舍入的尾部差异；下一首必须完成整个融合窗口，续段在真实解码 EOS 结束，不为 metadata 差异追加静音。前一首仅容许该范围内的末尾补齐，并按剩余窗口总量检查，不能逐块放行明显缺失的尾部。无损音频仍只容许末帧舍入，明显截断和解码错误继续回退。失败提示区分下一首缓存、当前音源缓存和制作阶段，日志保留完整异常原因。

Android 解码器首次 seek 只移动 extractor；尚未提交输入时不 flush 新 codec，避免丢失启动时自动提交的 AAC/FLAC 初始化数据。已提交输入但还没有输出时需要 seek，则 reset/configure/start 重新提交配置；已有输出时正常 flush。零长度 EOS 输出直接释放，不读取可能为 null 的 PCM buffer；携带最后一段 PCM 的 EOS 则完整消费后结束。失败状态增加简短原因，未知错误显示异常类型，详细路径和调用栈只进入日志。`work/android-automix-decoder-regression` 用可控的 Android API 替身运行实际解码器源码，覆盖首次/再次跳转、空 EOS、携带音频的 EOS 及完整 WAV 制作；这不替代实机解码验证。

2026-10-15 三星 SM-S9360 实测：系统 MediaExtractor 读取 native FLAC 时，约 245 个输入包之后时间戳回到 0，多个 FLAC 帧被分配进同一输入；`SEEK_TO_PREVIOUS_SYNC` 也可能落在目标之后。同一完整文件从不同位置解码会丢失不同长度的尾部。已缓存、以 `fLaC` 开头的本地 FLAC 改由 `FlacFrames` 解析 STREAMINFO 与帧头，按真实采样编号建立索引，并将完整的单个 FLAC 帧交给同一系统 MediaCodec；输入容量按最大帧调整，逐帧验证 CRC16，seek 保证从目标之前的 FLAC 帧开始。其他格式继续使用平台提取器。无损长度检查保持不变，不补静音、不放宽容差。该手机上 0、7.927、100.123、190.1 秒四个位置的解码均零缺帧，独立进程中的完整 6 秒融合加续段制作成功。主应用安装后的音频交接和听感尚未重新验证，证据在 `work/automix-device-20261015`。

原生交接预热：WAV 额外包含 cue 前最多 3 秒的 A 原调音频。第二播放器在此段静音启动，旧源保持正常音量；检测到文件时钟连续推进后，必要时在静音前置段内 seek 对齐。根据 seek 完成且恢复输出后真实文件时钟的残余误差，补偿下一次对齐目标，最多修正四次，且目标必须留在 cue 前。解决单次 seek 未计算异步耗时、导致每次融合都因残余时钟差被取消的问题。seek 完成且时钟再次推进、两侧时钟差不超过 80 毫秒时，cue 前约 96 毫秒开始线性交接。预热卡住、对齐失败或错过 cue 时保持旧源并正常切歌。预热不计入 B 已听进度，取消预热不会跳过 B 前奏。文件进度转换扣除前置段；本地试听工具也跳过此段，避免重复 A 尾部。

变调预热：制作时检测整段音高自动化，需要变调的一侧先读取 cue 前最多约 93 毫秒的原音频，以原调预热 FFT 和 overlap-add，相应预热音频不写入成品。整个融合使用 512 帧块（44.1kHz 下约 11.6 毫秒）更新变调参数，替代 4096 帧的约 93 毫秒步进；下一首仍保留连续尾段。`work/automix-preview/preview.ps1` 可只构建 core 并导出本地 WAV，无需重建或安装 APK。完整试听使用用户提供的 The Color Violet 和 Heartless 两个 MP3 转换出的 PCM WAV。

同一组相邻歌曲的制作任务和成品在暂停、音频焦点中断、拖动进度时保留，不重新分析或渲染。拖到融合点之前会重新停放同一成品，抵达点位正常融合；拖到点位之后（包括刚过点位）使用正常切歌，不补播尾部，再拖回之前仍可复用。播放器和控制器分别持有文件引用，取消预备播放器只释放其引用，交接后仍播放同一 WAV，最后一个引用释放才删除文件。

融合点位和剩余秒数都以歌曲播放进度为准，交接保护不再按现实时间超时。制作完成后，播放详情页显示“距融合点还剩 XX s”（剩余时间向上取整），暂停期间停止递减；暂停或拖回点位前仍刷新状态，清除过期的“已错过”提示。Android 异步 seek 尚未完成时，状态使用用户选择的位置，暂停交接检查，完成后继续读取真实音频进度。暂停指令立即取消静音预热播放器，避免暂停淡出期间仍开始交接，制作任务和成品继续保留。

预备播放器停放后按当前音频进度独立检查预热时机，不再等待首页/后台的 100–250 毫秒轮询来启动。控制器认可播放器已开始的预热，迟到的界面轮询不会将它当作错过点位取消。两侧时钟已经对齐时，交接容许最多 250 毫秒的调度迟到；时钟未对齐、输出冻结、超过容差或主动拖过点位仍回退，不向后补播。暂停、切歌和取消预备播放器会使旧预热检查失效。

队列变化、手动切歌和设置变化会取消过期后台任务。单个临时文件上限 256 MiB；只保留当前播放和当前相邻歌曲的成品，下次进程启动清理上次遗留文件。分析失败、源不可解码、文件超预算或错过切入点时使用正常切歌。视频、私人漫游、单曲循环、一起听跟随端不启用；AI DJ 保留组间推荐过渡，仅组内混音。

目前原生输出接入的是 Android MediaPlayer 后端。桌面后端未提供 AutoMix 输出能力。原包已移除外部模型权重，保留其 DSP 回退与内嵌 EQ 权重。

验证：合成音频经过真实引擎渲染（采样率/声道转换、和声与默认智能模式）、WAV 结构与尾段信号、取消清理、进度映射、播放元数据交接不重开音源、过期切入点与设置关闭回退。实际设备的切入延迟和听感仍需实机验证。
